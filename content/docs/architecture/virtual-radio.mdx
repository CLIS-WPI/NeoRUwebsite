## The deterministic virtual radio

The virtual radio stands in for the RF hardware. For the same input it produces the same output, bit for bit, every time. That turns radio behaviour into something a regression test can check, on any machine and in CI, with no radio attached.

It is the basis for the next validation steps. In Phase 2 it becomes a real-time virtual radio, and at Level 3 it lets NeoRU be tested against a real DU before any radio hardware is involved.

## The BFP compression codec

Uncompressed I/Q samples would need far more fronthaul bandwidth than a typical link provides. Block floating point (BFP) reduces it. Samples are grouped by resource block, the group shares one exponent, and each sample keeps a shorter mantissa.

NeoRU's codec has been checked against:

- the O-RAN CUS-plane specification;
- real DU traffic.

<Callout title="Component readiness, not system readiness">
  Both components are complete on their own. Fronthaul packet I/O and end-to-end integration are part of Phase 2.
</Callout>
