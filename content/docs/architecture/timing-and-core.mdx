<Lead>An O-RU works to a fixed rhythm. At 30 kHz subcarrier spacing a slot lasts 0.5 ms and holds 14 OFDM symbols, and every symbol has a deadline. The real-time core exists to meet those deadlines, and to show when it does not.</Lead>

## The slot clock

The timing core drives a precise slot clock. Work is scheduled against it, and each time a thread wakes later than planned, the event is recorded. A late wake-up is the earliest sign that a deadline is at risk, so it is treated as data rather than noise.

## Recording and execution

The **event ring** records what happened and when, without slowing the path it observes. The **executor** runs the scheduled work, and the **core plan** describes how that work is laid out across CPU cores.

## Checking the host before starting

Real-time behaviour depends on the machine as much as on the code. The host platform profile checks, before startup:

- that the cores reserved for real-time work are isolated;
- that memory and devices are local to the right NUMA node;
- that PCIe links run at the expected width and speed;
- that timers behave as required.
